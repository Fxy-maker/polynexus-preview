## 1. 阶段目标

阶段 5 只解决一个问题：

把“已经能稳定重复做分析”推进到“更像专业用户每天愿意依赖的工作流”。

这一阶段的关键词：

- 专业可信度
- 导入顺手
- 序列友好
- 导出完整
- 工作流闭环

## 2. T1 结论

### 2.1 阶段五不是从零开始

阶段五最重要的判断不是“还缺多少底层算法”，而是“哪些底层能力已经存在，只差一个能被用户稳定使用的入口”。

当前现状已经很明确：

- T4 导入向导不是新发明，现有 `ImportSuggestion` 和 `ImportSuggestionDialog` 已经足够作为第一版地基。
- T2 校准参数管理不是新系统，现有 calibration schema 和 recent calibration 机制已经说明数据面基本可复用。
- T3 mask 工作流不是完整图形编辑器项目，现有 SAXS mask 参数和 WAXS 边界文案足够支撑第一版最小闭环。
- T6 导出包不是“从无到有”，而是把现有 `figures / data / report / metadata` 输出收成更稳定、更可理解的交付结构。

### 2.2 阶段五最小模型

阶段五的最小模型不是“每个专业能力都做满”，而是：

- 只做高频场景。
- 只暴露已经有底层支撑的那部分能力。
- 每个入口都能形成小闭环。
- 所有子任务都尽量复用现有主窗口和现有数据结构，不另起一套工作流。

### 2.3 明确不做的事

- 不在阶段五追求所有仪器格式全覆盖。
- 不同时扩展所有 technique 的高级专业功能。
- 不做完整 LIMS / ELN / 远程任务平台。
- 不做完整图形化 mask 编辑器。
- 不把 AI 调参产品化能力混进阶段五。
- 不为了“专业感”强行重构主窗口、数据库和 orchestrator 主干。

## 3. 各任务最小闭环

### P5-T2. SAXS / WAXS 校准参数管理最小闭环

最小用户故事：

用户能为当前 `technique + submodule` 保存一套常用校准参数，并在下次分析前一键恢复，不需要重新手填。

这一版只做：

- 基于现有 calibration schema 的可保存、可恢复、可复用闭环。
- 作用域限定为 `technique + submodule`。
- 明确区分“日常复用参数”和“完整仪器重校准工作流”。

这一版不做：

- 完整仪器 profile 管理器。
- 多设备、多实验站、多版本 calibration 库。
- 复杂文件校验和 profile 迁移工具。

验收标准：

- 至少一套 SAXS 配置、至少一套 WAXS 配置可保存并恢复。
- 重启软件后仍可恢复。
- 缺失或不兼容的配置会给出明确提示。

### P5-T3. mask 工作流最小闭环

最小用户故事：

用户能理解当前分析是否启用了基础 mask 逻辑，能调整关键阈值，并在结果或日志里看到直接反馈。

这一版只做：

- 复用现有 SAXS `dummy_val / ddummy / beamstop_pollution_threshold / auto_detect_beamstop`。
- 明确 WAXS 当前只保留边界说明，不假装支持完整可视化 mask 设置。
- 把参数调整、运行拦截、日志反馈和结果反馈接成闭环。

这一版不做：

- 自由画多边形 mask。
- 2D 图像交互编辑器。
- 独立 mask 文件格式和跨项目共享库。

验收标准：

- 用户能在 GUI 中理解当前 mask 行为。
- 不合理阈值会被拦截或明确告警。
- 至少一类结果反馈会体现 mask 影响。

### P5-T4. 导入向导最小闭环

最小用户故事：

用户拖入或选择一个常见文件 / 目录后，系统能给出建议的 `technique / submodule / input_mode`，用户确认后直接带回主工作台。

这一版只做：

- 基于现有 `ImportSuggestion` 的建议式导入，不做强制自动执行。
- 支持常见单文件、常见目录、常见序列命名模式。
- 对无法可靠识别的情况给出建议和回退，而不是静默猜测。

这一版不做：

- 全自动无确认导入。
- 特别激进的文件名推理规则。
- 跨多目录、多样品批量导入编排器。

验收标准：

- 导入常见 SAXS / WAXS / DSC / IR / NMR 数据时，至少能减少一部分手工选择。
- 失败时用户能继续回到普通主工作台流程。
- 建议结果能稳定带回主窗口状态。

### P5-T5. 序列分析与批处理体验增强

最小用户故事：

用户导入目录或序列数据后，能更清楚地知道系统把它当成了什么模式、正在跑什么、结果应该从哪里看。

这一版只做：

- 强化 static / directory / sequence / strain / temperature 的状态提示。
- 补齐多文件和序列结果在 GUI 内的摘要入口。
- 补强 batch 与 sequence 的边界说明，避免“能跑但不知道跑的是什么”。

这一版不做：

- 完整并行任务框架重写。
- 大规模批处理队列调度器。
- 独立序列项目管理器。

验收标准：

- 用户能更容易判断当前模式。
- 多文件 / 序列结果在 GUI 里有稳定可见入口。
- batch 和 sequence 的区别不再只藏在日志里。

### P5-T6. 更完整的导出包与阶段回归补齐

最小用户故事：

用户拿到输出目录后，能直接知道哪些是主结果、哪些是图、哪些是表、哪些是报告，而不是靠猜文件名。

这一版只做：

- 基于现有导出结构统一 `figures / data / report / metadata`。
- 把主交付物命名、目录结构和提示做一致。
- 为阶段五新增入口补最小回归。

这一版不做：

- 完整论文投稿套件。
- 自动生成复杂 zip 发布物。
- 复杂模板化排版系统。

验收标准：

- 单文件、序列、joint 三类输出结构尽量一致。
- 用户能看懂导出结果目录。
- 阶段五新增能力有对应最小回归保护。

## 4. 推荐顺序

阶段五正式执行顺序调整为：

1. `P5-T1 阶段五范围与最小模型确认`
2. `P5-T4 导入向导最小闭环`
3. `P5-T2 SAXS / WAXS 校准参数管理最小闭环`
4. `P5-T3 mask 工作流最小闭环`
5. `P5-T5 序列分析与批处理体验增强`
6. `P5-T6 更完整的导出包与阶段回归补齐`

原因：

- T4 已经有现成地基，最容易先形成一个真实闭环。
- T2 和 T3 专业价值更高，但它们更依赖边界清晰，不适合先散着做。
- T5 适合放在导入和参数入口之后收口体验。
- T6 必须压在后面，否则前面结构没定，导出会反复返工。

## 5. T1 验收结果

T1 现在可以视为完成，因为以下问题已经明确：

- 阶段五每条子线的最小用户故事已明确。
- 哪些能力只做 GUI 闭环、哪些只保留底层边界，已经明确。
- calibration / mask / import wizard / export package 的范围已经收口。
- 下一步应切到 T2，而不是继续在导入链路上做无边界巡检。

## 6. 下一步入口

下一步直接进入 `P5-T2 SAXS / WAXS 校准参数管理最小闭环`，第一刀保持足够小：

1. 复用现有 calibration schema、字段 hint、最近一次 calibration 复用入口。
2. 只补“如何保存 / 复用 / 确认当前校准在生效”的最小 GUI 闭环。
3. 先覆盖 SAXS，再确认 WAXS 在阶段边界内如何复用同一套心智模型。
4. 不改底层积分、拟合或引擎算法，只补用户可见流程。

## 7. 阶段回归底线

阶段五每完成一个任务，至少回归这些场景：

1. GUI 能正常启动，切换 technique 不报错。
2. 单文件分析仍可运行。
3. 样品库、历史记录、batch 预设原有能力不回归。
4. 导入文件、目录、序列数据时不会把用户带到不可用状态。
5. calibration / mask 改动后会有明确反馈。
6. 导出目录仍可生成，且结构可理解。
7. 新入口至少有对应的定向测试。

## 8. 阶段完成定义

满足下面条件即可视为阶段五完成：

- 用户可管理并复用至少一套 SAXS / WAXS 校准配置。
- 2D 散射相关流程具备最小 mask 工作流。
- 导入过程对 `technique / submodule / input_mode` 的识别更顺手。
- 序列分析和 batch 结果在 GUI 层面更像完整工作流。
- 导出结果更接近可交付包，而不只是文件堆。
