## 1. 阶段目标

阶段 4 只解决一个问题：把“能完成一次分析”推进到“能稳定重复做很多次”，让高频用户不必每次重新配参数、重新调图、重新组织批任务。

这一阶段的关键词：
- 模板化
- 参数复用
- 图风复用
- 批处理复用
- 历史可回放

## 2. 当前判断

从当前代码和回归结果看，阶段 4 的主目标已经达成：

- 配置面板已具备命名参数模板的保存与载入闭环
- 图表编辑器已具备样式模板的最小复用闭环
- 历史记录已形成“恢复工作台状态 / 按原配置重跑 / 最小结果对比”的可用入口
- CLI batch 已具备 JSON 预设、最近任务重跑与常见失败反馈的最小复用能力

当前更合适的判断不是“还差一套大系统”，而是“阶段 4 已可收口，剩余工作转入可选优化”：

- `workers > 1` 仍是显式顺序降级，这属于后续能力增强，不再是阶段 4 的必需项
- history compare 仍是最小摘要对比，这属于后续体验深化，不再是阶段 4 的必需项
- 少量非主路径文案 / 日志一致性尾项可继续补，但不影响阶段 4 交付判断

## 3. 阶段边界

### 做什么？

- 给参数配置增加最小模板保存/载入能力
- 给图表编辑增加可复用的样式模板能力
- 给批处理增加任务预设或最小重跑入口
- 让历史记录不只是“查看”，而是更接近“再次运行同类任务”
- 收口当前批处理相关的高频体验缺口

### 不做什么？

- 不在这一阶段做完整工作流编排平台
- 不做复杂多步骤 pipeline 模板系统
- 不做远程任务调度、多机执行或队列系统
- 不在这一阶段重构全部 technique config 模型
- 不把 GUI、CLI、样品库、AI 调参模板一次性统一成一个大模板中心

## 4. 任务拆分

### T1. 阶段四最小模板模型设计

目标：先定义“什么叫模板”，避免后续每一处都各存一套不兼容格式。

涉及文件：
- [polynexus/gui/main_window.py](/D:/PolyNexus/polynexus/gui/main_window.py)
- [polynexus/gui/widgets/chart_editor.py](/D:/PolyNexus/polynexus/gui/widgets/chart_editor.py)
- [polynexus/utils/config.py](/D:/PolyNexus/polynexus/utils/config.py)

任务内容：
- 明确参数模板、图表模板、批处理预设三类对象的最小字段
- 明确模板存储位置与命名策略
- 明确哪些模板先只服务 GUI，哪些需要同时兼容 CLI
- 明确“模板”和“历史记录快照”的边界

验收标准：
- 有一套可以落到代码中的最小模板定义
- 后续 T2/T3/T4 不需要各自重新发明数据结构

风险：
- 如果模板模型一开始做得太抽象，后面每一步都会被模板框架绑住

### T2. 参数模板最小闭环

目标：让用户可以保存一套常用分析参数，并在下一次快速载入。

涉及文件：
- [polynexus/gui/main_window.py](/D:/PolyNexus/polynexus/gui/main_window.py)
- [polynexus/utils/config.py](/D:/PolyNexus/polynexus/utils/config.py)

任务内容：
- 在配置区增加“保存当前参数模板 / 载入模板”的最小入口
- 第一版只支持当前 technique + 当前子模块的命名模板
- 模板至少保存当前配置面板可见字段
- 载入模板后，配置面板应立即回填
- 对模板重名、空名称、模板不兼容等情况给出明确提示

验收标准：
- 用户可以保存一套 SAXS/WAXS/DSC/IR/NMR 常用参数
- 重新打开软件后仍能看到并载入该模板
- 载入后无需手工重新填写同样参数

风险：
- 如果把所有 technique 特例一口气吞进去，第一刀会过重

## 5. 推荐实施顺序

建议按下面顺序推进：

1. `T1 阶段四最小模板模型设计`
2. `T2 参数模板最小闭环`
3. `T3 图表样式模板最小闭环`
4. `T5 历史记录重跑与结果对比补强`
5. `T4 批处理任务预设与重复执行入口`
6. `T6 批处理体验收口与回归补齐`

原因：
- 先做参数模板，最贴近日常高频使用
- 图表样式模板和参数模板天然相邻，都是“减少重复劳动”
- 历史重跑可以复用前面的模板/回填基础
- 批处理预设放后一点，更容易用前面的模板思路收敛，而不是单独长成一套系统

## 6. 回归检查

阶段 4 每完成一个子任务，至少检查下面这些场景：

1. GUI 正常启动，配置区与样品库不报错
2. 单文件分析仍能正常运行
3. 保存模板后重启软件，模板仍可见
4. 载入模板后，配置面板值与保存时一致
5. 图表样式模板应用后，预览立即更新
6. 历史记录恢复与重跑不混淆
7. CLI batch 原有用法不回归
8. 批处理失败时提示仍清楚

## 7. 阶段完成定义

满足下面条件即可视为阶段 4 完成：

- 用户可以保存并复用常用分析参数
- 用户可以保存并复用一套常用图表样式
- 历史记录更接近“可重跑任务”而不是静态台账
- 批处理入口不再只是一次性命令，而有最小复用能力

## 8. 开工建议

阶段 4 推荐从 `T2 参数模板最小闭环` 开始。

第一刀建议保持足够小：
- 先只做 GUI 配置区的命名模板
- 先只覆盖当前 technique + 当前子模块
- 先不把图表模板、batch 预设和 AI 调参模板合并

这样最容易形成“保存一套常用参数 -> 下次直接载入”的第一条真实闭环。
