# PolyNexus 阶段3起步清单

## 0. 当前进度

- [x] S1 第一小步已完成：批次区已补充最近分析摘要，并增强多文件可见性
- [x] S2 第一小步已完成：可从批次行打开只读详情窗口，查看文件与分析记录
- [x] S3 第一小步已完成：支持编辑样品名/别名，并补充重名与缺失校验
- [x] S4 第一小步已完成：支持编辑批次名/技术标签，并可替换或移除已挂接文件
- [x] S5 第一小步已完成：可从批次行直接带回主分析区，回填文件、技术与最近子模块
- [x] S6 第一小步已完成：样品库内未完成的导出报告入口已隐藏收口

## 1. 目标

阶段 3 不再优先补底层去重规则，而是把阶段 2 已经打通的样品库最小闭环，继续往“真实可连续使用”的方向推进。

这一阶段的关键词：
- 信息完整
- 操作顺手
- 状态可判断
- 从样品库回到分析流程更自然

## 2. 当前判断

阶段 2 已经解决了这些基础问题：
- 样品库可以真正打开和浏览
- 可以新建样品
- 可以给样品新建批次并挂接单个原始文件
- 主分析结果会落到样品 / 批次体系里
- 已补上最小去重、复用和失败提示

但从高频用户视角看，样品库现在仍然更像“能用的最小骨架”，还不是“顺手的日常入口”。

## 3. 阶段3建议任务

### S1. 批次详情补全

目标：
让用户点开一个样品后，不只是看到批次名，而是能快速确认这个批次到底包含什么。

建议内容：
- 在批次区显示更完整的文件信息
- 显示最近一次分析时间 / 技术 / 状态
- 显示该批次下已有多少条分析记录
- 为多文件批次预留最小展示方式

验收标准：
- 用户无需打开数据库即可判断批次是否已导入、已分析、分析了几次
- 用户能看出批次里挂了哪些文件

---

### S2. 批次详情交互

目标：
让批次不只是“可看”，还可以做最基本的继续操作。

建议内容：
- 支持查看该批次下的文件列表
- 支持从批次回到对应文件或输出目录
- 支持最小的“重新分析 / 打开结果目录”入口
- 支持查看该批次最近一次分析摘要

验收标准：
- 用户从样品库进入后，能继续完成至少一个后续动作，而不是只能浏览

---

### S3. 样品编辑最小能力

目标：
避免样品一旦建错名字或别名后只能继续堆新样品。

建议内容：
- 支持修改样品名
- 支持修改别名
- 支持最小的合并/重命名前校验

验收标准：
- 用户能修正常见录入错误
- 不会因为轻微命名问题被迫新建重复样品

---

### S4. 批次编辑最小能力

目标：
让“批次名写错、文件挂错、技术选错”这类高频小错误可修正。

建议内容：
- 支持修改批次名
- 支持替换或移除已挂接文件
- 支持修改批次技术标签
- 对正在被分析记录引用的批次做温和提示

验收标准：
- 用户能在 GUI 内修正常见批次录入问题
- 不需要手动碰数据库

---

### S5. 样品库与主分析流联动补强

目标：
让样品库真正成为工作入口，而不只是结果归档处。

建议内容：
- 从样品库选中批次后，支持一键带入主分析区
- 自动回填 technique / submodule / 输入文件
- 对无法直接回填的情况给出清楚提示

验收标准：
- 用户可以从样品库发起下一步分析
- “库内浏览”和“主分析工作台”之间不再割裂

---

### S6. 导出报告入口收口

目标：
处理当前仍处于占位状态的“导出报告”，避免它长期成为半成品入口。

建议内容：
- 要么补一个最小导出能力
- 要么暂时隐藏/禁用该入口
- 如果保留入口，至少说明将导出什么内容

验收标准：
- 样品库中不再存在意义不明的高可见入口

## 4. 建议优先顺序

建议按下面顺序推进：

1. `S1 批次详情补全`
2. `S2 批次详情交互`
3. `S5 样品库与主分析流联动补强`
4. `S3 样品编辑最小能力`
5. `S4 批次编辑最小能力`
6. `S6 导出报告入口收口`

原因：
- 先补“看不清”的问题，再补“不能继续做”的问题
- 先增强高频浏览与继续分析路径，再补修订能力
- 导出报告应放在样品库主流程更稳定之后

## 5. 不建议在阶段3做的事

- 不建议现在就做完整样品主数据治理
- 不建议现在就做复杂批量导入向导
- 不建议现在就做多用户/同步/权限体系
- 不建议现在就做大规模数据库结构重构

## 6. 阶段3完成定义

满足下面条件即可认为阶段 3 完成：
- 样品库里的批次信息足够支持日常判断
- 用户能从样品库继续进入后续分析动作
- 常见录入错误可以在 GUI 中修正
- 样品库不再给人“只能看，不能继续干活”的感觉
