# PolyNexus 开发路线图

## 1. 目标

这份路线图只做一件事：把 PolyNexus 后续改进拆成一组小步、可回退、可验收的阶段，避免一次性大改带来连锁 bug。

当前总体判断：

- 项目优势已经比较明确：多技术分析、样品库、联合分析、AI 调参。
- 当前主要短板不在“功能想法不够多”，而在“体验闭环还不够稳”。
- 后续应优先修复高频用户马上会撞到的问题，再逐步增强专业能力。

## 2. 推进原则

1. 先修高频痛点，再做扩展功能。
2. 先做低耦合、低风险、可单独验证的改动。
3. 一次只处理一类问题，不把 UI、数据库、算法、AI 同时大改。
4. 每一阶段结束后都能单独回归，不依赖后续阶段才能成立。
5. 所有新增入口都要有最小闭环，避免出现“按钮在、能力不完整”的半成品体验。

## 3. 优先级分级

### P0

- 中文乱码、README 可读性、明显错误提示缺失
- 空入口或占位入口的处理
- 基础稳定性和用户信任感问题

### P1

- 样品库最小闭环
- 联合分析能力补完
- 基础结果沉淀和可追溯性

### P2

- 模板化批处理
- 导入向导
- 图表与参数复用能力

### P3

- SAXS/WAXS 校准与 mask 工作流
- AI 调参产品化
- 更完整的专业分析工作流增强

## 4. 阶段规划

### 阶段 0：问题盘点与回归基线

目标：
先把问题边界和后续回归方式定义清楚，不着急改代码。

范围：

- 形成问题清单，按 `P0/P1/P2/P3` 分类。
- 形成模块地图：`GUI`、`SampleDB`、`Joint`、`Batch/CLI`、`AI Tune`。
- 形成回归检查表。

不做什么：

- 不改任何业务逻辑。
- 不调整数据库结构。
- 不补功能。

验收标准：

- 有一份明确的问题列表。
- 有一份最小回归脚本或人工检查清单。
- 后续每个阶段都能引用同一套回归标准。

风险：

- 风险最低，但如果盘点不完整，后续容易返工。

---

### 阶段 1：体验与信任感修复

目标：
先修“用户一打开就会注意到”的问题，不动核心算法。

范围：

- 修复 README 和 UI 文案乱码。
- 统一文案来源，逐步收敛到 `i18n`。
- 清理空入口和占位按钮：
  `样品库 > 新建样品`、`导出报告` 这类入口要么补最小功能，要么先禁用并给出明确说明。
- 补齐关键错误提示和失败反馈。

不做什么：

- 不改核心分析流程。
- 不做数据库重构。
- 不引入新分析模块。

验收标准：

- 主界面、样品库、联合分析相关页面不再出现明显乱码。
- README 能正常展示并引导安装/启动。
- 所有保留在界面上的入口都能完成最小闭环，或明确提示暂不可用。
- 典型失败场景下，用户能知道失败发生在哪一层。

风险：

- 看似是文案问题，实际可能牵涉编码、历史文件和局部硬编码混用。

---

### 阶段 2：样品库最小闭环

目标：
把“结果存储”升级成“工作流入口”，让样品库真正可用。

范围：

- 明确 `样品 -> 批次 -> 分析记录` 的使用模型。
- 补齐新建样品、补录批次、挂载原始文件的最小流程。
- 明确样品搜索、筛选、选择后的交互路径。
- 评估数据库默认存储位置，规划迁移到用户目录。
- 设计文件去重和基本元数据更新策略。

不做什么：

- 不在这一阶段做复杂批量管理界面。
- 不扩展高级统计分析。
- 不大改分析引擎。

验收标准：

- 用户可以从样品库新建一个样品并挂接至少一种技术数据。
- 能查看该样品对应批次和分析记录。
- 分析结果和样品/批次之间的关系清晰可追溯。
- 不会因为重复导入同一文件而制造明显脏数据。

风险：

- 数据模型一旦定错，后续联合分析和批处理都会受影响。

---

### 阶段 3：联合分析能力补完

目标：
把项目最有差异化的部分做实，形成可演示、可交付的联合分析能力。

范围：

- 补全 `joint plotters` 中未完成的图表生成逻辑。
- 明确第一版联合分析支持的组合和前提条件。
- 完善联合分析结果展示和诊断摘要。
- 明确联合分析报告的最小输出格式。

建议第一批优先图：

- DSC / WAXS / SAXS 结晶度对比
- `Tm vs long period`
- `IR vs DSC crystallinity`
- 相关矩阵热图

不做什么：

- 不做全自动多模型联合拟合平台。
- 不扩展成复杂建模系统。

验收标准：

- 至少 3 到 4 张核心联合分析图可稳定生成。
- 联合分析结果能被样品库和结果页消费。
- 对缺失技术数据、参数缺失等情况有降级处理。

风险：

- 如果样品库数据组织不稳，这一阶段会被拖累。

---

### 阶段 4：模板化批处理

目标：
提升高频使用效率，把“会用一次”变成“能重复用很多次”。

范围：

- 分析参数模板
- 图表样式模板
- 批处理任务模板
- 历史任务重跑与结果对比

参考方向：

- 借鉴 OriginPro 的模板化思路，但实现上保持贴合当前架构。

不做什么：

- 不做复杂工作流编排平台。
- 不做过度抽象的模板系统。

验收标准：

- 用户能保存一套常用参数并用于下一批样品。
- 用户能复用图风格，不必每次重新调图。
- 批处理历史能被查看和重跑。

风险：

- 如果模板层设计过重，容易把简单流程复杂化。

---

### 阶段 5：专业工作流增强

目标：
补齐散射和实验分析用户真正关心的专业可信度工具。

范围：

- SAXS/WAXS 校准参数管理
- mask 工作流
- 导入向导：自动识别技术、子模块、实验条件
- 序列分析与批处理体验优化
- 更完整的导出包

不做什么：

- 不在这个阶段追求所有仪器格式全覆盖。
- 不同步扩展所有技术方向的高级功能。

验收标准：

- 散射类用户可以明确设置和复用关键几何/校准信息。
- 导入复杂数据时，用户不必频繁手动猜测子模块。
- 导出结果更接近真实交付物。

风险：

- 与底层 I/O、配置、GUI 耦合较深，改动面会明显变大。

---

### 阶段 6：AI 调参产品化

目标：
把 AI 调参从“可运行能力”变成“可解释、可复用、敢在真实工作里用”的功能。

范围：

- 展示每轮改动内容、原因、结果和回滚原因。
- 将 AI 最佳参数保存为模板。
- 把模型名和策略配置从硬编码迁出。
- 增加人工确认应用的流程。

不做什么：

- 不追求完全自动黑盒调参。
- 不把 AI 调参作为主流程强绑定。

验收标准：

- 用户能理解 AI 为什么调参数。
- 用户能选择是否接受参数。
- 调参结果可沉淀、可复用、可追踪。

风险：

- 最容易引出“效果不稳定”和“用户不信任”的双重问题，必须晚于前几阶段推进。

## 5. 推荐执行顺序

建议按下面顺序推进：

1. 阶段 0：盘点与回归基线
2. 阶段 1：体验与信任感修复
3. 阶段 2：样品库最小闭环
4. 阶段 3：联合分析能力补完
5. 阶段 4：模板化批处理
6. 阶段 5：专业工作流增强
7. 阶段 6：AI 调参产品化

原因：

- 这个顺序把“稳定性、数据组织、差异化能力、效率增强、专业增强、AI 增强”分开了。
- 每一步都能形成独立收益，也便于阶段性停下。

## 6. 每阶段统一验收清单

每做完一个阶段，都建议至少检查下面这些项：

- 软件能正常启动
- 主界面切换技术不卡死
- 单文件分析可运行
- 结果页可展示
- 图表页可打开
- 导出功能未回归损坏
- 样品库基础浏览可用
- 联合分析入口不报错
- 日志和错误提示仍然可读

## 7. 下一步建议

当前最适合立刻进入的是阶段 1。

阶段 1 的实际拆分建议：

1. 文档与界面乱码盘点
2. README 修复
3. 样品库和联合分析相关文案收敛
4. 空入口处理策略
5. 关键错误提示补齐

如果后续继续推进，可以直接在这份路线图下面追加每个阶段的任务单和完成记录。
