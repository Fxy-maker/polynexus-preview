# SAXS 变温序列闭环工作台设计

**日期：** 2026-07-17  
**范围：** SAXS 原位变温序列结果页的第一轮体验优化  
**状态：** 待用户评审

## 目标

让一次 SAXS 变温序列分析在结果生成后形成清晰的最小闭环：用户能快速知道序列是否需要人工确认、主要风险是什么、下一步应该查看图表还是回到配置重跑，并能沿用现有确认与导出能力完成收口。

这轮只优化结果页的信息组织和操作入口，不修改 SAXS 科学算法、证据计算、结果表字段含义、风险判定规则或导出格式。

## 当前上下文

主窗口目前按“数据 → 配置 → 结果 → 图表 → 历史”组织。结果页已经存在：

- 结果摘要、风险提示和下一步文本；
- 结构化结果表，SAXS 变温表包含温度、阶段、`L`、`lc`、取值来源、熔融窗口状态和可靠性状态；
- 结果审阅、结果对比、结果确认区域；
- 图表页、配置页、导出动作的现有跳转入口。

问题是这些能力分散在多个区域。用户看到结果后，需要自己把摘要、风险文本、表格和按钮拼成一个行动顺序；变温序列尤其缺少“先看什么、哪些帧值得确认、确认后如何收口”的可见主线。

## 设计方案

### 1. 结果页增加“变温序列审阅”闭环卡

在结果页现有结果摘要之后、结果审阅之前放置一个仅对 `saxs.temperature` 序列结果显示的闭环卡。静态 SAXS、拉伸 SAXS、其他技术和没有结果的状态保持现状。

闭环卡从上到下包含：

1. 标题和状态：例如“变温序列已生成 · 待确认”。
2. 紧凑指标行：总帧数、可用/待确认帧数、熔融窗口帧数、温度轴状态。只展示结果中已有且可明确解释的字段；字段缺失时使用统一空值，不做猜测。
3. 一句主判断：优先复用现有结果摘要、风险摘要和下一步文本，避免在 GUI 重新计算科学结论。
4. 主操作区：查看温度总览、回到配置重跑、标记当前结果已确认。动作按钮根据状态显示或禁用。
5. 轻量辅助说明：提示用户详细数值仍在下方结构化结果表中，图表和导出仍由现有入口负责。

卡片不自动弹窗、不自动重跑、不自动改变当前 tab。分析结束后仍由现有流程跳转到结果页，用户可以决定下一步。

### 2. 状态与信息来源

新增一个纯展示模型，负责把现有参数、结果和分析证据整理成 UI 所需字段。它不重新判断 `lc`、熔融窗口或低 q 风险，只读取已有结构：

- 行数和序列指标来自当前结构化结果模型/结果参数；
- `lc` 状态、诊断帧数和熔融窗口帧数复用现有 SAXS 历史/语义 helper；
- 风险和下一步文字复用现有结果语义方法；
- 结果确认沿用现有 `_toggle_current_result_confirmation`；
- 图表与配置动作只调用现有 tab 跳转方法。

建议将纯整理逻辑放在 `polynexus/gui/saxs_temperature_review_service.py`，返回一个可测试的字典或小型数据类，例如：

```text
{
  "visible": true,
  "status": "review" | "ready" | "empty",
  "frame_count": 12,
  "review_frame_count": 3,
  "melting_window_frame_count": 2,
  "temperature_axis_text": "已识别" | "待确认" | "—",
  "headline": "……",
  "risk_text": "……",
  "next_text": "……",
  "confirmed": false,
}
```

具体字段名以现有数据结构为准；服务层不得因为缺失字段而抛异常，也不得用 `r_squared` 等单一拟合指标推断整条序列可用。

### 3. 操作行为

- “查看温度总览”：切换到现有图表 tab，保持当前结果和图表生成逻辑不变。
- “回到配置重跑”：切换到现有配置 tab，不自动改值、不自动启动分析。
- “标记结果已确认”：调用现有结果确认逻辑，更新确认文字和闭环卡状态；如果现有确认逻辑不可用，按钮保持禁用并保留原有结果审阅区域。
- 导出：继续使用顶部和结果表现有导出动作，不在闭环卡中增加新的导出实现，避免出现两个导出状态源。

按钮应有明确的主次层级：存在风险时“查看温度总览”为主动作；没有未确认风险且结果可用时“标记结果已确认”为主动作。按钮文字和状态必须经过 i18n，至少补齐中文和英文。

## 文件边界

### 新增

- `polynexus/gui/saxs_temperature_review_service.py`：纯函数/轻量数据模型，负责变温序列闭环卡的展示数据整理。
- `tests/test_saxs_temperature_review_service.py`：覆盖完整证据、缺失字段、已确认、非变温子模块和异常输入。

### 修改

- `polynexus/gui/main_window_results_mixin.py`：构建闭环卡控件、按钮和布局，保持结果页现有区域顺序。
- `polynexus/gui/main_window_output_mixin.py`：在显示变温结果时刷新闭环卡；无关技术继续走现有路径。
- `polynexus/gui/main_window_retranslate_mixin.py`：补充语言切换时的卡片标题、状态和按钮文本刷新。
- `polynexus/gui/i18n.py`：增加中文/英文文案。
- `tests/test_ui_function_streamlining.py` 或新增定向 GUI 测试：验证仅 SAXS 变温结果显示卡片、按钮跳转不触发自动运行、确认动作复用现有入口。

不修改 `polynexus/core` 下 SAXS 算法、证据生成和结果字段生产逻辑。

## 异常与降级

- 没有结果、当前子模块不是 `saxs.temperature` 或结果不是序列：卡片隐藏，现有结果页完全可用。
- 结果字段不完整：卡片显示可获得的指标，缺失项显示统一空值；不阻断结果表和导出。
- 证据整理 helper 发生异常：记录 warning，隐藏新增卡片，保留现有摘要/表格/审阅区域。
- 用户点击查看图表或回配置后返回：不丢失当前结果，不改变现有 tab 记忆和配置值。
- 确认失败：保留待确认状态，并通过现有日志/错误反馈提示，不伪装成已确认。

## 测试策略

1. 纯服务测试：
   - 完整变温结果生成正确的帧数、待确认数和熔融窗口数；
   - `diagnostic_only`、低置信度和缺失温度轴的状态能被展示；
   - 已确认结果显示收口状态；
   - 静态、拉伸和空输入返回隐藏/空模型；
   - 非字典、嵌套结构异常输入不抛出 GUI 级异常。
2. GUI 定向测试：
   - 创建主窗口后，非 SAXS 变温上下文不显示新卡；
   - SAXS 变温结果上下文显示新卡并刷新文本；
   - 查看图表和回配置只改变 tab，不调用 `_run_analysis`；
   - 确认按钮沿用现有确认状态更新。
3. 回归测试：
   - 运行现有 SAXS 结果表、历史、结果语义和主窗口相关测试；
   - 运行完整 `pytest`，确认其他技术和 CLI 不受影响。

## 不在本轮范围

- 新建逐帧图表定位或帧筛选工作台；
- 修改 SAXS 温度序列排序、`lc` 路径选择、mask、校准或熔融窗口算法；
- 重新设计全局导航、配置表单或历史页；
- 引入新的持久化数据库表或新的导出格式；
- 为静态和拉伸 SAXS 同步建设同等复杂度的闭环卡。

## 验收标准

- SAXS 变温序列分析结束后，结果页首屏能看到序列状态、关键计数和一条明确的下一步建议。
- 用户无需阅读底部日志即可知道应先查看图表、回配置重跑还是确认结果。
- 新增按钮不触发隐式重跑，且不会破坏现有结果表、审阅、对比、确认和导出。
- 缺失证据或旧结果仍可查看、复制和导出。
- 现有测试全部通过，新增纯服务测试覆盖降级路径。
