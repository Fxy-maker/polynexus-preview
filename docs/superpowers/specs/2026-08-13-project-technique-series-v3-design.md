# Project Technique Series V3 Design

## Decision

Add `project.technique.series.v1` for two or more files belonging to one
technique. The adapter owns deterministic ordering and recipe metadata only;
the existing provider engines remain authoritative for numeric analysis.

## Contracts

- The request resolves one technique and two or more non-blocked indexed
  artifacts. Mixed techniques remain blocked.
- Ordering is normalized relative project path (or an explicit integer
  `parameters.series_order` map when supplied). The order is persisted in each
  recipe step as `artifact_index` and `source_order`.
- Each step references exactly one recipe artifact by index. Replicate grouping
  is an explicit optional request parameter and defaults to `unknown`; no group
  is inferred from filenames.
- A source hash mismatch blocks before provider execution and package creation.
- Packages project conservative `run_part_of_request` relations only when the
  same request hash is explicit. No sample/batch/formulation conclusion is
  generated by the workflow.

## Migration

Single-input routes and DSC behavior remain unchanged. Existing callers may
continue passing explicit relations to `package`; automatic relations are
added only when none are supplied.
