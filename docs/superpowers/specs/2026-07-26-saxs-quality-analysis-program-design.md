# SAXS 质量与分析体系路线设计

日期：2026-07-26
状态：已获用户路线确认，等待阶段 0 实施计划
关联 Goal：建立可解释、可验证、可降级的 PolyNexus SAXS 数据质量与分析体系

## 1. 目标

将 SAXS 从“尽量完成分析并给出质量分数”提升为“尽可能挽救可用信息，并明确每个结论的可信边界”的科学分析闭环。

首个纵向试点是变温 1D 已积分 q-I 曲线的 Guinier 分析。试点必须同时打通质量报告、确定性分析、序列证据、可信度分级和结果展示/导出边界，再横向扩展到其他方法和模式。

## 2. 非目标

- 第一阶段不重写现有 SAXS 核心算法。
- 第一阶段不同时实现 Porod、Kratky、2D 和完整 AI 自动化。
- 不把 qRg < 1.3 当作所有聚合物 SAXS 场景的通用有效性证明。
- 不自动生成缺失温度帧的伪实测曲线。
- 不在证据不足时将结果提升为主结论或 paper figure candidate。

## 3. 公共质量契约

逐步建立以下最小公共对象和语义：

- `DataQualityReport`：记录原始/有效/排除数据量、异常比例、数据轴问题、处理动作和来源。
- `MetricEvidence`：记录一个物理指标的数值、拟合证据、不确定度、适用性、风险和来源。
- `RescueCandidate`：记录一个确定性或 AI 提出的处理候选及其参数变化。
- `RescueValidationReport`：记录候选重新分析后的硬门槛、软分数、拒绝原因和最终决策。
- 可信等级：`Quantitative`、`Trend`、`Diagnostic`、`Unusable`。

契约规则：原始数据不可覆盖；清洗不可静默；缺失数据保持缺失；AI 只能提出候选；候选必须经过确定性分析和物理验证；每帧和每个指标独立分级。

## 4. 分阶段路线

### 阶段 0：质量契约与验收夹具

定义最小 DTO/原因码/分级规则，建立合成与故障注入数据夹具。验收重点是报告可序列化、原始数据可追溯、处理动作可重放。

### 阶段 1：变温 1D Guinier 纵向闭环

覆盖已积分 q-I 温度序列：确定性清洗、Guinier 候选区间、拟合、Rg/I0/不确定度、qRg、点数、残差、低 q 风险、温度序列异常和每指标分级。AI 先处于 shadow/确认模式，只推荐候选区间或参数。

Guinier 结果只有在场景假设、有效 q 范围、拟合证据和物理合理性共同满足时才可定量；层片 Bragg 主导、强光束挡板污染或明显不满足 Guinier 假设的数据只能降级或拒绝该指标。

### 阶段 2：1D 方法族

在阶段 1 模板上依次接入 Porod、Kratky、不变量/整体散射量，并将现有 `L`、`lc`、`phi_c`、`Q*`、Bragg/Lorentz/IDF 证据接入统一契约。方法可不同，但输出必须共享数值、证据、适用性、不确定度、风险和等级。

### 阶段 3：静态/变温/应变统一

共享质量报告和证据结构，但保留模式专用科学判据：变温关注相变与峰演化，应变关注取向和各向异性，静态关注单样品结构参数。

### 阶段 4：2D 探测器与取向

记录坏像素、热点、饱和、beamstop、无效像素比例、空 bin、几何参数、beam center、积分覆盖率和扇区积分风险，并把图像质量传递到 1D 曲线与结构参数。

### 阶段 5：序列级救援

处理 q 轴/温度轴/应变轴统一、重复和缺失条件、邻帧峰追踪、异常帧、相变区阶段感知连续性以及“真实突变 vs 处理伪影”。邻帧只能辅助参数选择和质量判断，不能替代缺失实测曲线。

### 阶段 6：AI 救援

AI 识别问题类型、推荐清洗/拟合候选、推荐峰追踪窗口并解释决策。自动化分为 shadow、confirm-only、safe auto-accept 三步；任何自动接受都必须通过重新分析、数据保真、物理参数漂移和序列证据硬门槛。

### 阶段 7：产品闭环与发布验收

将质量、救援和可信度传递到 Results Workbench、参数表、Figure Gallery、Figure Editor、Manifest、Export、History 和 AI 调参记录。最终验收包括合成数据、故障注入、真实数据、重启 GUI、导出包和人工科学审查。

## 5. 阶段门槛

每个阶段必须有：

1. 明确的输入/输出契约。
2. focused regression tests。
3. 失败、降级和 AI-off 路径。
4. 原始数据和处理证据可追溯。
5. `python scripts/verify.py --task <task-card> --changed --types` 的实际结果。
6. 原子 checkpoint 和项目记忆更新。

发布前另外运行 full/boundary verifier，并保留真实数据和人工科学审查作为独立门槛。

## 6. 执行边界

这是架构、科学语义和跨模块任务。每个阶段拆成独立任务卡和实现计划，遵循 `AGENTS.md`：先设计、再 TDD、再实现、再验证、再用显式文件白名单提交；不自动 push、merge、deploy，不修改真实回归数据或生成输出。
